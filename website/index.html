Write the workflow once. Run it reliably, in every language.

ORBIT is a declarative language and durable runtime for work that spans services. You describe the steps, their order and what happens when they fail. The compiler checks every step against its worker's contract before anything runs, and the runtime carries it through retries, timeouts, crashes and compensation.

How it works

  1. 01

    Declare

    Task contracts describe what each worker accepts and returns. Workflows describe steps, dependencies, conditions, retries, timeouts and compensation. Dependencies follow from the data a step reads.

  2. 02

    Check

    The compiler type-checks every step input, every reference and every optional value, rejects cycles, and lowers the workflow to a versioned, content-hashed intermediate form.

  3. 03

    Run

    The runtime records every decision as an event before acting on it. Workers in any language poll for tasks over HTTP or gRPC. A crash at any point resumes from history.

Mistakes surface before deployment

A step that can be skipped produces an optional value. Using it where a value is required is a compile error, with the exact location and a suggested fix, not a null pointer at three in the morning.

Every diagnostic has a stable code and is documented in the diagnostics reference. The same checks run in your editor through the language server.

Failures are part of the program

When a payment is declined, ORBIT runs the compensations of the steps that already succeeded, in reverse order, and records every decision. The history is the source of truth: inspect it with orbit logs, or export it as OpenTelemetry traces.

What the language covers

Typed contracts

Schemas, optional types, records, lists and maps. Inputs and outputs are validated by the compiler and again by the runtime.

Retries and timeouts

Attempt limits, fixed or exponential backoff, non-retryable error codes, per-attempt, queue and workflow deadlines.

Compensation

Declare the action that undoes a step. On failure, cancellation or timeout, completed steps are compensated in reverse.

Fan-out

for item in list runs a step per element with its own retries and idempotency key, limited by max_parallel.

Child workflows

Start another workflow as a durable child with a deterministic id, type-checked against its input and output.

Durable timers

sleep 24h survives restarts and needs no worker. Conditions decide at run time whether a step runs.

Workers in the language you already use

Business logic stays in your services. Each SDK registers task handlers, receives work, and reports results; all six are tested against the real runtime, including over mutual TLS.

Guarantees, stated precisely

Durable
Every state change is committed to SQLite or PostgreSQL before it takes effect. State is rebuilt from history on restart.
At-least-once
ORBIT never claims exactly-once. Each task carries an idempotency key that is stable across retries and redeliveries, so workers can make side effects safe.
Immutable versions
A workflow name and version are bound to a content hash. Running executions keep the definition they started with.
Secure by configuration
Admin, shared-worker and per-worker credentials, TLS and mutual TLS, with tasks restricted per identity.
